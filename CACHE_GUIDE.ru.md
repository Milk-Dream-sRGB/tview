# Памятка: кеш, токены и контекст в панели tview

Короткий справочник, чтобы быстро вспомнить, что значат числа в панели и как по ним принимать решения.
Только на русском. Это памятка пользователя, не часть README мода.

## 1. Главное в трёх строках

- **Контекст** (значок со шкалой в середине) — насколько «толстый» чат сейчас. Это один показатель размера.
- **Четыре числа справа** (чтение, запись, ввод, вывод) — сколько стоил **последний ход целиком**, суммой по всем его запросам.
- Тревожиться стоит не о большом чтении, а о **скачке записи** и о **раздутом контексте**.

## 2. Что показывает каждый значок

| Значок | Название | Смысл |
|---|---|---|
| Яркая коробка, серая середина | Чтение кеша (cache read) | Сколько токенов контекста сервер взял из готового кеша. Дёшево: ~0.1 от цены обычного ввода |
| Бледная коробка, яркая середина | Запись в кеш (cache write) | Новые токены, добавленные в кеш на этом ходу. 1.25× (или до 2× на часовом кеше) от обычного ввода |
| Перевёрнутая стопка | Запросы в ходе (0.53.0) | Сколько запросов к модели сделал ход, стоит после записи в кеш. Объясняет, откуда большое чтение: контекст × число запросов |
| Точка внизу | Новый ввод (input) | Токены вне кеша: хвост после последней метки кеша. **Не размер твоего сообщения.** С 0.53.0 виден только от 50 за ход (странное поведение, возможный промах кеша) |
| Стрелка вверх | Вывод (output) | Что написал Claude. Самые дорогие токены, ~5× от обычного ввода |
| Снежинка | Таймер кеша | Шесть лучей по 10 минут, гаснут по одному. Все погасли — кеш остыл |
| Линия с засечкой (`176k`) | Контекст | Сколько занято в чате. Оранжевый с 200k, красный с 400k |
| `80/5` | Сообщения / картинки | Отправлено сообщений и картинок в чате |

## 3. Как читать числа

**Ход ≠ один запрос.** «Ход» — весь ответ на твоё сообщение. Если Claude вызвал 17 инструментов, это 17 запросов, и каждый заново читает весь контекст.
Поэтому чтение 3–5M в панели нормально: контекст 176k × ~17 шагов ≈ 3M. Это не «в кеше лежит 3M».

**Все четыре числа справа — суммы за весь ход**, а не за последний запрос. Единственное «мгновенное» число — контекст (состояние на последнем запросе).

**Что входит в вывод.** Не только видимый текст: ещё команды и скрипты для инструментов, содержимое записанных файлов (файл перевода на 313 строк — основная часть 17k), реплики между шагами и финальный ответ. Поэтому вывод бывает большим при коротком итоговом сообщении.

**Оценка размера контекста за ход:** чтение + запись + ввод ≈ контекст.

**Почему «новый ввод = 10 токенов» для двух абзацев.** Сообщение почти целиком уходит в **запись** кеша, в «ввод» остаётся только хвост. Размер своего сообщения по панели не видно. Для русского ориентир: 1 токен на 2–3 символа, два абзаца ≈ 300–600 токенов.

**Откуда данные.** Счётчики самого API (по каждому запросу), мод суммирует их за ход (`turn.complete`). Им можно доверять, но категории зависят от кеша, а не от «что отправил я».
Для разбивки контекста по составу (инструкции, инструменты, история, файлы) есть встроенная команда `/context`.

## 4. Сколько это стоит (в «условных токенах обычного ввода»)

Точные веса лимита подписки Anthropic не публикует. Ориентир по коэффициентам API:

| Статья | Коэффициент |
|---|---|
| Чтение кеша | 0.1× |
| Запись в кеш | 1.25× (часовой кеш до 2×) |
| Новый ввод | 1× |
| Вывод | ~5× |

Пример хода: чтение 3.0M, запись 88k, вывод 36k ≈ 300k + ~110–175k + ~180k ≈ **600–650k** условных. Чтение даёт примерно половину, хотя числом в десятки раз больше остальных.

Реальную цену 1% лимита смотри в `/tview` («сколько токенов стоит 1% лимита», самый дорогой чат). Это надёжнее коэффициентов выше.

## 5. Сигналы и что делать

| Что видишь | Значение | Действие |
|---|---|---|
| Чтение большое, запись 1–10k | Нормальная работа, кеш тёплый | Ничего |
| Запись ≈ весь контекст (сотни k) | Кеш остыл, контекст записан заново — дорогой ход | Не делать пауз больше часа в большом чате; сжимать до паузы |
| Контекст растёт, 200k → оранжевый | Каждый ход дорожает, модель хуже держит детали | Планировать `/compact` на границе задачи |
| Контекст красный (400k+) | Дорого и неточно | Новый чат с итогом |
| Вывод большой | Лимит уходит на длинные ответы | Просить короче, точечные правки |
| Чтение резко выросло за ход | Много шагов с инструментами | Сужать задачу: «найди X в файле Y», а не «изучи проект» |

## 6. Как не плодить лишнюю запись

Запись неизбежна для нового текста. Вредна **лишняя**:

| Что раздувает | Как избежать |
|---|---|
| Остывший кеш | Не уходить на паузу больше часа в толстом чате |
| Чтение файлов целиком | Просить точечно |
| Большие выводы команд и логи | `head` / `grep`, не вставлять портянки |
| Смена модели, правка CLAUDE.md или MCP посреди чата | Делать в начале нового чата |
| Тяжёлые поиски по проекту | Отдавать агентам (свой контекст, назад приходит итог) |
| Картинки и PDF | Прикладывать по необходимости |

## 7. Лимит 5 часов и срок кеша

- Пока лимит ниже 100%, кеш живёт ~1 час (подписка). На 97% ничего не меняется.
- Срок падает до 5 минут, когда сессия уходит в **usage overage** (платный объём сверх плана). Это моё понимание поведения движка, не подтверждено официальной документацией.
- Без Extra usage на 100% тебя просто остановят до сброса, кеш при этом не укорачивается.
- Мод всегда считает по часу (`CACHE_TTL_MS`), поэтому в перерасходе снежинка может врать.

**Сценарий:** 97%, сброс через 20 минут, кеш на 40 минут. Ждать сброса разумно: кеш переживёт ожидание (40 > 20), продолжишь на свежем окне. Ограничение одно: не ждать дольше, чем осталось до остывания.
Один агентный ход на 3–5M чтений может съесть остаток 3% и выбросить в блокировку посреди задачи.

## 8. Когда делать `/compact`

| Контекст | Действие |
|---|---|
| До ~150k | Рано |
| 150–250k | Хорошая зона, на границе задачи |
| 250–400k | Уже стоит |
| 400k+ | Лучше новый чат с итогом |

Правила:
1. Компактить **между задачами**, не посреди: детали теряются в пересказе.
2. Пока **кеш тёплый** (снежинка горит): сжимающий запрос читает контекст дёшево.
3. **До паузы**, а не после.
4. С подсказкой: `/compact сохрани решения, текущий формат и открытые вопросы`.
5. Задача сменилась полностью — новый чат чище и дешевле.
6. Картинки в пересказе, скорее всего, теряются; при необходимости приложить заново.

**Компакт перед уходом.** Пример 176k → ~70k:

| Сценарий | Оплата (усл. токены) |
|---|---|
| Компакт и уход | чтение 176k (0.1×) + пересказ (~15–30k × 5) + запись нового ~70k ≈ 170–250k |
| Уход без компакта, возврат после остывания | запись всех 176k ≈ 220–350k |
| Каждый следующий ход из 17 шагов | чтение 176k против 70k: ~300k против ~120k |

Вывод: компакт перед долгим уходом (больше ~40 минут до остывания) выгоден и окупается примерно за один ход. До ~40 минут ради кеша не нужен.
Уходишь до завтра с другой задачей — новый чат с кратким итогом.

## 9. Известные ограничения мода

- Время жизни кеша жёстко 1 час; в перерасходе (5 минут) снежинка не знает.
- После ручного `/compact` снежинка не обновляется.
- Панель суммирует за ход, поэтому «запись 8k» может быть одним большим результатом инструмента, а не твоим текстом.
- Когда именно движок записывает новый контекст после `/compact` (сразу или на первом ходу), точно неизвестно; расчёты исходят из первого хода.
